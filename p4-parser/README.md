# P4 智能解析（自训模型 / 任意教务页面都能抽取）—— 待分工

> 这个目录是**留给别人做 P4 的工位**，不是主工程的一部分。
> 主工程（`src/`、`android/`、`cloudflare/`）**不要直接改**；做完由产品负责人统一整合。

## 一、目标（用户能感知的一句）

北化以外的教务页面（甚至北化改版后的页面）不用发版、不用手写适配器，**粘一个页面就能把课表/考试/成绩抽出来**。

## 二、先读这个再动手

`../Net.md` 的 **§2.6** 是 P4 的完整评估：结论是**不建议先自训模型**，而是先用已经落地的
**声明式规则包热更新**（`src/services/parser/rules.ts` + `../docs/adapters.md`）。
所以 P4 有两条路，请先跟产品负责人确认走哪条：

| 路线 | 交付内容 | 工作量 |
| --- | --- | --- |
| **A. 增强规则型（推荐）** | 更好的规则/选择器/正则 + 更多学校的规则包（走已有的签名下发通道） | 小，随时能合进主工程 |
| **B. 自训模型** | 一个**本机推理**的小模型（不联网） + 训练脚本 + 标注数据 + 评测结果 | 大（需要机器与标注） |

## 三、不管走哪条，这些红线不能碰

1. **数据默认留在本机**：解析必须在设备上完成。要把页面内容发到任何服务器/第三方模型前，**必须先问产品负责人**（`../AGENTS.md` 第 5 条）。
2. **真实姓名不入库**：样本一律脱敏（学生"智小汇"、学号 `2025040999`、教师"教师A~S"）。参考文件 `../../个人课表查询.html` 含真实姓名，**禁止复制进本目录**。
3. **不许引入需要联网的推理服务**（云函数调大模型不算 P4，那属于 P5）。
4. **改主工程要另开分支/PR**：本目录里的东西不许直接 `import` 到 `src/`，整合由产品负责人做。

## 四、交付物（放这个目录里）

```
p4-parser/
├── README.md          ← 本文件
├── NOTES.md           ← 你的方案/进展/遇到的坑（给整合的人看）
├── rules/             ← 路线 A：规则包 JSON（含学校 id、版本号、选择器）
├── model/             ← 路线 B：模型文件与体积说明（要能塞进 APK 或走热更）
├── train/             ← 路线 B：训练脚本 + 数据说明（**数据本身脱敏后再放**）
├── fixtures/          ← 脱敏样本页面（可入库）
└── report.md          ← 评测结果：抽了多少页面、准确率、失败样例
```

## 五、验收清单（自测完再交）

- [ ] 用**脱敏样本**能跑通，且**断网可用**；
- [ ] 失败时不崩、给出人能看懂的原因（不合格的行/缺失字段要指出来）；
- [ ] 体积与耗时写清楚（APK 现在 6.6 MB，模型多大、首次解析多久）；
- [ ] 给出"改版演练"结果：把样本页故意改坏，再看解析是降级还是报错；
- [ ] 报告里写明**哪些是已验证、哪些没验证**（`../AGENTS.md` 第 6 条：不许把"没跑过"说成"通过"）。

## 六、怎么跟主工程对接（整合时看这里）

- 主工程现有的接入点是 **`src/services/parser/rules.ts`** 的声明式规则 + `catalog/index.json` 的 `adapters` 字段
  （签名清单、每天一次限频、`validateRulePack()` 白名单校验都已实现）；
- 主工程的测试要求：**新增测试文件必须同时登记进 `package.json` 与 `scripts/build-apk.ps1`**，否则等于没跑；
- 出包只走 `powershell -NoProfile -ExecutionPolicy Bypass -File scripts\build-apk.ps1`。
