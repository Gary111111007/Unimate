日期：2026-10-02 ｜ 范围：`p4-parser/` 独立原型，不含主工程整合、真机和 UI ｜ 运行环境：Node.js v24.19.0。

## 一、结论

- 路线：A，声明式规则 + 启发式识别；没有训练模型，没有联网推理。
- 已实现 JSON 优先、HTML 兜底、字段别名、内部 ID 过滤、脱敏诊断、last-good 语义。

## 三、已验证

1. **JSON / HTML 双通道**
   - JSON：嵌套载荷数组、常见载荷键、响应体多编码一层。
   - HTML：表头与值配对，不依赖固定列号。
2. **别名表跨列序**
   - 把“课程名称”和“学分”两列对调后仍解析出 4 条成绩。
3. **改版演练**
   - 表头“课程名称”改成“课程”仍能识别。
   - 删除可选“绩点”列后只降级该字段，其他字段不受影响。
4. **数据清洗**
   - 内部 ID `ABCDEF0123456789` 不当作课程代码；同一单元格同时出现内部 ID 和标准课号时优先标准课号。
   - 学分、绩点从 `3.5 学分`、`绩点 3.8` 中抽取。
5. **失败与空状态**
   - 解析失败时 `keepLastSuccessful()` 保留上一次成功记录。
   - 空表格返回 0 条记录，不伪造 `0` 分或 GPA。
6. **隐私与离线**
   - 解析过程不发起 `fetch`：测试中打桩 `fetch`，调用计数为 0。
   - 诊断与统计扫描不到课程名、教师名、学号。
   - 诊断只包含字段名、行数、失败步骤；不打印原文值。
7. **菜单发现**
   - 从脱敏页面的链接中发现成绩、考试、课表入口；没有请求任何教务接口。
8. **主工程现有样本复用**
   - P4 规则包可映射成主工程建议的 `adapterId + kind: academic + rules` 外形，独立测试已覆盖。
   - 识别主工程 41 KB 的脱敏 jqGrid 考试样本，得到 9 条考试记录；验证了“表头表 + 数据表分开”的 jqGrid 结构。

## 四、未验证

1. **真实教务页面**
   - P4 自己的 4 份 fixtures 都是合成脱敏样本；另外复用了主工程现有 41 KB 北化脱敏 jqGrid 样本，但仍没有第二所学校或更新版本的真实页面，因此“任意教务页面都能抽取”尚未成立。
2. **主工程接入**
   - 没有修改 `src/`、`android/`、`cloudflare/`。
   - 当前规则包 schema 与主工程 `validateRulePack()` 不同，不能直接下发。
3. **真机与 UI**
   - 没有 WebView 注入、没有成绩页/考试页 UI、没有本地持久化、没有提醒接入。
4. **HTML 复杂性**
   - 轻量正则 HTML 解析器尚未覆盖嵌套表格、复杂 `rowspan`、iframe、JS 动态渲染、无表头表格。
5. **GPA 口径**
   - 当前只解析单门课绩点，不计算总 GPA，也不实现“学校记录优先于本地计算”。
6. **TypeScript 全量类型检查**
   - 当前项目本地未安装 `tsc`；P4 测试用 Node `--experimental-strip-types` 运行，未做独立 `tsc --noEmit`。
7. **签名下发**
   - 规则包尚未走 Ed25519 签名清单链路；这是整合阶段的工作。
