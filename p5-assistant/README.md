## 一、目标（用户能感知的一句）

App 里有个助手 **Uni**：能问"我明天几点上课""这周有几节课""二课还差多少分"，它用**本机已有的数据**回答，
需要生成式能力时才调用大模型 —— 而**大模型的 Key 绝不能进 APK**。

## 二、先读这个再动手

`../Net.md` 的 **§2.7** 是 P5 的完整评估（三件必须先想清的事）：

1. **Key 泄露**：客户端直连模型 = 把 Key 打进 APK = 等于公开。**必须经自己的代理**（现成的 `cloudflare/sync-worker` 就是同一套基础设施）。
2. **被刷**：代理上要有配额/限频（项目里已有 `SYNC_RATE_LIMITER` 的用法可照抄）。
3. **合规**：生成式 AI 有专门要求；**如果把课表/姓名发给第三方模型，就是数据出境 + 个人信息处理**（`../AGENTS.md` 第 5 条）。
   更稳的做法：**先做"本机规则问答"**（不需要模型就能答上面那三类问题），把大模型留给"开放问答"，并且让用户自己决定要不要开。

## 三、红线

1. **API Key 只在服务端 secret 里**（例如 `npx wrangler secret put LLM_API_KEY`），**不许写进 `src/`、APK、请求体或日志**。
2. **默认不把用户数据发给模型**：讲清什么会发（比如只发"明天有几节课"这种抽象问题）、什么不会（课表明细、姓名、学号、照片）。
   要发就必须先让用户在界面上明确同意，并在「关于」里如实写明。
3. **不许改主工程的账号/同步逻辑**：你只加"助手"这一块能力，鉴权/数据读写通过下面第四节的接口约定。
4. **不许引入需要联网才能用的核心功能**：断网时助手要能降级成"本机问答"。

## 六、怎么跟主工程对接（整合时看这里）

- 主工程已有：账号体系（`/v1/login` 等）、端到端加密同步、`cloudflare/sync-worker`（Worker + Pages 中继 + 限频）
  —— 代理**复用同一套**，不要另起一套域名（`*.workers.dev` 在大陆不通，见 `../PRD.md` 11.47）；
- 助手要读的数据在 `src/stores/db.ts`（课表 `timetables/courses`、记事 `notes`、二课 `records`）；
  整合时由产品负责人决定"哪些数据允许进提示词"；
- 多语言/无障碍、暗色主题、字号四档这些全局设置**不用你管**，主工程会自动套上；
- 测试与出包规则同上：新增测试文件要登记进 `package.json` 与 `scripts/build-apk.ps1`。
