# P5 AI 助手（Uni 接大模型）—— 待分工

> 这个目录是**留给别人做 P5 的工位**，不是主工程的一部分。
> 主工程（`src/`、`android/`、`cloudflare/`）**不要直接改**；做完由产品负责人统一整合。

## 一、目标（用户能感知的一句）

App 里有个助手 **Uni**：能问"我明天几点上课""这周有几节课""二课还差多少分"，它用**本机已有的数据**回答，
需要生成式能力时才调用大模型 —— 而**大模型的 Key 绝不能进 APK**。

## 二、先读这个再动手

`../Net.md` 的 **§2.7** 是 P5 的完整评估（三件必须先想清的事）：

1. **Key 泄露**：客户端直连模型 = 把 Key 打进 APK = 等于公开。**必须经自己的代理**（现成的 `cloudflare/sync-worker` 就是同一套基础设施）。
2. **被刷**：代理上要有配额/限频（项目里已有 `SYNC_RATE_LIMITER` 的用法可照抄）。
3. **合规**：生成式 AI 有专门要求；**如果把课表/姓名发给第三方模型，就是数据出境 + 个人信息处理**（`../AGENTS.md` 第 5 条）。
   更稳的做法：**先做"本机规则问答"**（不需要模型就能答上面那三类问题），把大模型留给"开放问答"，并且让用户自己决定要不要开。

## 三、红线

1. **API Key 只在服务端 secret 里**（例如 `npx wrangler secret put LLM_API_KEY`），**不许写进 `src/`、APK、请求体或日志**。
2. **默认不把用户数据发给模型**：讲清什么会发（比如只发"明天有几节课"这种抽象问题）、什么不会（课表明细、姓名、学号、照片）。
   要发就必须先让用户在界面上明确同意，并在「关于」里如实写明。
3. **不许改主工程的账号/同步逻辑**：你只加"助手"这一块能力，鉴权/数据读写通过下面第四节的接口约定。
4. **不许引入需要联网才能用的核心功能**：断网时助手要能降级成"本机问答"。

## 四、交付物（放这个目录里）

```
p5-assistant/
├── README.md          ← 本文件
├── NOTES.md           ← 方案/进展/坑（给整合的人看）
├── proxy/             ← Worker 代理脚本 + 部署说明（secrets 只写名称，不写值）
├── prompts/           ← 提示词与"能问什么/不能问什么"的边界说明
├── ui/                ← 助手界面的原型（截图/HTML 原型即可，不要直接改 src/）
└── report.md          ← 评测：问了哪些问题、答得对不对、失败样例、成本估算（每千次多少元）
```

## 六、怎么跟主工程对接（整合时看这里）

- 主工程已有：账号体系（`/v1/login` 等）、端到端加密同步、`cloudflare/sync-worker`（Worker + Pages 中继 + 限频）

## 七、要不要自己租服务器？（产品负责人 2026-09-26 问过，这里留个结论）

**先分清两件事**：P5 是**调别人的大模型 API**（代理转发 JSON 文本），不是自己训/跑模型。

| 你想干的事 | 需要的机器 | 2核2G ¥10/月 那台够吗 |
| --- | --- | --- |
| 只做代理：客户端 → 你的服务 → 模型 API | 1 核 512MB 都能跑（Node/Go/Python 都行） | **够，而且绰绰有余** |
| 在服务器上跑本地大模型（7B 量化等） | 至少 16GB 显存 / 大内存 GPU 机器 | **完全不够**（2GB 内存连加载都做不到） |

所以：**这台机器只能当"转发代理"，别指望它在上面跑模型。**

### 7.1 真正要先确认的四件事（比 CPU/内存重要得多）

1. **服务器在境内还是境外？**
   - **境内**机器：访问不了 OpenAI/Claude（会被墙/封 IP），只能调**国内模型**（DeepSeek、通义、智谱、月之暗面等）；
     而且对公网提供 HTTP 服务按规矩需要 **ICP 备案**（用非标准端口跑一阵通常没人管，但心里要有数）。
   - **境外**机器（香港/美国等）：能调 OpenAI，但**大陆手机连它可能很慢/丢包**（小厂线路尤其明显），且同样要域名 + 证书。
2. **手机能不能稳定连到它？** 这是决定成败的一条 —— 大陆 5G 到境外廉价小机的实际速度，必须**真机测**，别只看商家标的 10M/50M。
3. **HTTPS 证书与域名**：Android 上 APK 调 `https://` 需要**受信任的证书**，自签证书会直接连不上 → 要么域名 + Let's Encrypt，要么走第 7.2 节那条现成的路。
4. **你愿意多养一台机器吗？** 续费、被扫、被墙、被 DDoS、小厂跑路 —— 都是额外负担，对比赛项目属于"非必要复杂度"。

### 7.2 更省事的做法：直接用我们已经跑通的 Cloudflare 路线（推荐）

主工程**已经有**一套现成的"服务端 + 密钥 + 限频 + 大陆可达域名"：

| 现成的东西 | 在哪儿 | 对 P5 有什么用 |
| --- | --- | --- |
| Cloudflare Worker（可加路由） | `cloudflare/sync-worker/` | 加一个 `/v1/chat` 就是 P5 的代理；模型 Key 放 **secret**（`npx wrangler secret put LLM_API_KEY`），永远不进 APK |
| Pages 同域转发 | `cloudflare/pages/_worker.js` | 手机已经能访问 `https://unimate3.pages.dev`（**实测 200/1.3s**），免备案、免证书，不用再买域名 |
| 限频 | Worker 里 `SYNC_RATE_LIMITER` 的用法 | 照抄即可，防止 Key 被刷 |

**结论**：P5 的代理**优先加在现有 Worker 上**，不要一上来就租服务器。等真的有"必须自己跑一个常驻服务"的理由（比如要跑向量库、要长时间后台任务），再考虑租机器 —— 那时也不该是 2G 内存的共享小机。

### 7.3 如果确实要租（买之前照着核一遍）

- [ ] 确认机房在**境内还是境外**，并据此选定模型提供商（决定整个方案能不能跑通）；
- [ ] 确认是 **KVM 独立虚拟化**（不是 OpenVZ 共享内核，后者装不了 Docker/自定义内核）；
- [ ] 确认能**装 Node 或 Python**，能用 systemd/Docker 常驻；
- [ ] 确认支持**绑定自己的域名**并方便签免费证书（Let's Encrypt）；
- [ ] 确认带宽是**独享还是峰值共享**、有没有月流量上限；
- [ ] **真机实测**：用手机 5G 访问它的 `/health`，看延迟与丢包（这一步别省）；
- [ ] 心里有数：¥10/月这档通常是超售共享，**适合演示、别当生产**；Key 泄露/被刷的风险要靠限频 + 额度告警兜住。

### 7.4 无论走哪条路，这三条硬规矩不变

1. **模型 Key 只许放服务端 secret**（Worker secret 或服务器环境变量），**绝不许进 `src/`、APK、请求体或日志**；
2. **默认不把课表/姓名/学号发给模型**：要发必须先让用户在界面上明确同意，并在「关于」里如实写清"发了什么、发给谁"（`../AGENTS.md` 第 7、14 条）；
3. **代理必须限频**，并且要有"每天最多花多少钱"的心理预算（额度告警）。

> 详细评估见 `../Net.md` **§2.7**（那里写了 P5 的三件必须先想清的事）。

## 八、对"同学那版方案"的评审（2026-09-26）

同学的想法是：**搞一个服务器，Agent 分两层 —— 有网时接 DeepSeek 聊天，没网时只能跑基础命令**；
另外提到"自己蒸馏一个 DeepSeek 模型"、"用 MCP 直连 App 的所有接口，甚至一句话选课"。

**方向对了一半**：两层（在线 / 离线）是对的，这跟本文 §2、§3 的结论一致。
下面三条要改，否则会白花大量时间：

### 8.1 误区一：自己"蒸馏一个 DeepSeek"来做 Agent ❌

| 事实 | 说明 |
| --- | --- |
| 蒸馏/微调要 **GPU + 数据 + 标注** | 不是"租个 2核2G 的机器跑一下"能做到的；即便用现成开源权重去蒸馏，也要几十 GB 显存级别的机器 + 数据集 + 评测 |
| 那个 $10/月 的机器**连加载都做不到** | 2GB 内存跑不了 7B 量化模型；它只能做"转发代理" |
| 费用其实反了 | **API 比自建便宜得多**：DeepSeek 这类 API 是"每百万 token 几块钱"的量级，一个比赛演示问几百次也就**几块钱**；自建模型反而要 GPU 租金（几十到几百元/天） |

**结论**：不要蒸馏、不要自己跑模型。**接 API**（或国内模型的免费额度）才是 P5 的正解 —— 这也是本文 §2 早就写下的结论。

### 8.2 误区二："MCP 直连 App 的所有接口" ❌（数据边界搞反了）

关键前提：**用户的课表、记事、二课记录全在手机本机**（`AGENTS.md` 第 5 条）。
如果让**服务器**去调这些数据，就等于把用户数据上传到服务器 —— 既违反现有架构，也没必要。

正确的分工是：

| 谁 | 干什么 |
| --- | --- |
| **手机端（主工程）** | 持有数据、执行"工具调用"（查明天几点上课、这周几节课、空档、记事）。**数据不出手机** |
| **服务器（代理）** | 只转发"问题文本 + 模型回复"，持有 API Key，做限频。**它看不到课表明细** |
| **模型（DeepSeek 等）** | 只负责"理解问题、决定调哪个工具、把结果说成人话" |

也就是：**MCP / 工具调用要发生在端上，而不是发生在服务器上。**
模型只应该看到"明天有几节课"这种**抽象问题**，看不到姓名、学号、课程明细和照片。

### 8.3 误区三："一句话选课" ❌（超出产品范围，也踩硬规则）

- 本项目对教务系统是**只读**的：课表靠页面导入（`src/services/parser/`），**不代填表单、不代替用户操作学校系统**（`AGENTS.md` 第 2 条）。
- 所以"一句话选课"不能做，也**不许写进任何文案**（第 7 条：写了做不到的功能算事故）。
- 可以做的替代：**"一句话查课"**（"我明天有几节课""周三下午有空吗""这周哪几天要早起"），这些都在本机就能回答。

### 8.4 推荐的落地形态（也回答了"要不要租服务器"）

```
App（手机，数据都在这里）
   │  ① 离线：本机关键词/规则层直接回答常见问题（不联网，也不需要模型）
   │  ② 在线：把"抽象问题"发给代理 → 模型 → 答案回端上（工具调用在端上执行）
   ▼
代理：优先用现有 Cloudflare Worker（pages.dev 同域，免备案免证书，手机实测可达）
      Key 放 secret：npx wrangler secret put LLM_API_KEY
   ▼
模型 API（DeepSeek / 通义 / 智谱…）
```

**服务器结论**：这套结构里，代理就是个"转发 + 限频"的小服务 —— 现有 Worker 免费额度足够比赛用，
**不需要额外租机器**。真要自租，那台 ¥10/月 的机器也只能当这个代理，别指望在上面跑模型（见 §7）。

### 8.5 分工边界（避免两个人改同一份代码）

| 谁做 | 交付物放在哪 |
| --- | --- |
| **同学（P5）** | 本目录：`proxy/`（代理脚本或 Worker 路由草案）、`prompts/`（提示词 + 工具定义）、`ui/`（聊天界面原型，就是他截图里那个 Uni 页面）、`report.md`（评测与成本） |
| **主工程（我）** | 端上的数据访问与"工具执行"、离线关键词层、把聊天入口接进 App、限频与密钥的接入点 |

**红线**（已写进 `../AGENTS.md` 第 14 条）：不许直接改 `src/`、`android/`、`cloudflare/`；需要主工程配合就写进 `NOTES.md`。

### 8.6 需要同学先回答的三个问题

1. **用哪个模型？**（DeepSeek / 通义 / 智谱 / OpenAI）—— 决定 API Key 从哪来、服务器放境内还是境外；
2. **离线层打算怎么答？** 建议就是"本机关键词 + 本地数据"（不联网、不用模型），他截图里那句"试试离线查课"就是这个意思 —— **这部分不需要服务器，也不需要模型**；
3. **聊天界面放哪？** 他想做成 App 内一个页面（推荐），还是独立网页演示（现在的原型）？

## 九、怎么出一份「能拖到 Cloudflare Pages 的包」交给产品负责人（2026-09-26）

产品负责人要的东西长这样（`artifacts/cloudflare/unimate-cloudflare-<版本>-upload/`）：

```
unimate-cloudflare-v2.57-upload/
├── assets/                ← 构建产物（前端 bundle）
├── catalog/               ← 高校档案（清单 + 签名 + 各校 json）
├── _worker.js             ← ★ 必须在根目录：Pages 的 Advanced Mode 入口（同步 API + 密文中转）
├── index.html
└── sample-timetable.html
```

**它不是手工拷出来的**，仓库里有脚本负责生成：`scripts/make-pages-package.mjs`。

### 9.1 前置条件（两件，缺一不可）

1. **仓库是私有的**（匿名访问返回 404）→ 需要产品负责人在 GitHub 上把你加成协作者：
   `仓库 → Settings → Collaborators → Add people`（或者他给你一个临时 PAT）。
2. **代码要拉到 `main` 分支**：GitHub 上的 `main` 就是正式版；**不要**在别的分支上出包。

### 9.2 出包命令（三条，照抄即可）

```powershell
git clone https://github.com/Gary111111007/UnimateUL.git
cd UnimateUL
git checkout main

npm install                                   # 第一次会拉依赖，需要网络
npm run build                                 # 生成 dist/（前端产物）
node scripts\make-pages-package.mjs v2.57      # ← 生成要发给产品负责人的那个文件夹
```

最后会打印：

```
Pages 上传目录：…\artifacts\cloudflare\unimate-cloudflare-v2.57-upload
  文件 15 个 / 0.7 MB，根目录含 _worker.js
```

把 **`artifacts/cloudflare/unimate-cloudflare-v2.57-upload` 这个文件夹**发给产品负责人。
（跨人传输包成 zip 没关系 —— 他拖到 Pages 之前会解压；Pages 网页端只接受**目录**，不接受 zip。）

### 9.3 四个坑（都是我们踩过的）

1. **不要跑 `scripts\build-apk.ps1`** —— 那是打安卓 APK 的，需要 Android SDK，和你无关；
   你只需要 `npm install → npm run build → make-pages-package` 这三条。
2. **`artifacts/` 不在仓库里**（被 `.gitignore` 排除），所以必须自己构建，别指望 clone 下来就有。
3. **版本号参数只是命名用**（`v2.57` 可以换成任何字符串），它不影响包内容。
4. **Node 需要 18 以上**（建议 20/22）；Windows 下路径**尽量别带中文**，省得踩编码坑。

### 9.4 你的页面怎么进这个包（两种做法，选一个）

| 做法 | 步骤 | 适合 |
| --- | --- | --- |
| **A. 合进主工程（推荐，最终形态）** | 你把页面代码放到 **`p5-assistant/ui/`**（Vue 单文件组件或 HTML 原型都行），**不要直接改 `src/`**（`AGENTS.md` 第 14 条红线）；写清"放在哪个 tab / 怎么进入"到 `NOTES.md`；产品负责人负责合并进 `src/`。合并后你再跑 9.2 的三条命令出包 | 这个页面要成为 App 的一部分 |
| **B. 先独立看一眼效果** | 你自己建一个**独立的** Cloudflare Pages 项目（用你自己的账号），把自己项目的构建产物目录拖上去，只把 **URL** 发过来 | 只是想先验证界面/交互 |

**别做的事**：不要把自己那份产物直接覆盖到 `unimate3` 项目上 —— 那个站点还挂着同步 API 的 `_worker.js` 与 `catalog/`，
覆盖掉会让 App 的登录/同步/高校档案一起坏（`unimate3` 只能由产品负责人用 9.2 的包更新）。
