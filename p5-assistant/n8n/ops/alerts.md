## 一 为什么比赛 MVP 不做告警

| 前置条件 | 比赛 MVP 状态 |
| --- | --- |
| 常驻实例（`scheduleTrigger` 才有意义） | ❌ 只有一次性隔离实例，跑完即停 |
| 数据库（告警查询的对象） | ❌ 三张表都**未部署** |
| 通知渠道（企业微信 / 邮件 / webhook） | ❌ 未接，也**未授权**接 |
| 真实流量（基线的来源） | ❌ 没有。**没有流量就没有基线** |
| 观测自身的可靠性 | ⚠️ P09 刚把链路接上，还没有一天的运行数据 |

**没有基线的告警等于没告警**：写一个"p95 > 3s 就报警"，而 p95 从来没被测量过，
第二天一定被静音——**静音阈值比没有阈值更糟**，因为它制造"已经有人盯着"的错觉。

## 三 赛后要接的话，接什么

按 §9.3 与 §4.10 的错误分级，**最小可用的告警面只有三条**——
其余在 LLM / 缓存 / Redis 上线前都是空转，**先不要写**（写了就会被静音）：

| 优先级 | 条件 | 级别 | 依赖 |
| --- | --- | --- | --- |
| **P0** | 任一 `E_CONFIRM_INVALID` | 立即 | 可能是攻击尝试，要人工看一眼。**唯一一条"与 LLM 无关、现在就该有"的告警** |
| **P0** | `error_code = 'E_INTERNAL'` 占比 > 5%（5 分钟窗口） | 立即 | 需要常驻实例 + `agent_log` |
| **P1** | 上游连续失败 > 10 次（`E_UPSTREAM_TIMEOUT`） | 15 分钟内 | 同上 |

**明确不要先写的**：
- p95 延迟告警——**先把 `latency_ms` 变成真值**（`docs/observability.md` §4.3 的 `_meta` 旁路），
  否则告警逻辑永远在拿 `null` 做比较。
- LLM 费用告警——**先有 LLM**。费用硬上限是**闸门**（拒绝请求），不是告警；
  两者别混。§8.4 的限流数值至今仍是**待校准建议值**（OQ-08）。
- 缓存类告警——**先有缓存**。

## 四 告警分级与 `agent_error_handler` 的关系

§4.10 把错误分成三级，这是**告警分级的依据**：

| 分级 | 码 | 是否告警 | 本轮状态 |
| --- | --- | --- | --- |
| `client`（4xx） | `E_SCHEMA` / `E_VERSION_UNSUPPORTED` / 各类拒绝码 | **不告警**（唯一例外：`E_CONFIRM_INVALID` 要人工看） | 拒绝路径**已验证**（§13.6 #4，G4）；**告警未接** |
| `upstream` | `E_UPSTREAM_TIMEOUT` 等 | 按阈值告警 | 码已定义；**阈值未校准、告警未接** |
| `internal`（5xx） | `E_INTERNAL` | 立即告警 | `Shape Response` 已能产出该码（P11 修复）；**告警未接** |

**`agent_error_handler` 工作流不创建**——**已裁决**（产品负责人 2026-09-25，OQ-16 关闭）：
比赛版不单设第七个 Workflow，错误处理继续用**现有 Workflow 内的统一 Error Envelope**。
理由与影响见 `docs/observability.md` §八。该工作流列为**部署阶段可重新评估项**。

> ⚠️ **因此，本文件里没有任何一条告警是真的能用的**——没有错误处理器、没有通路、没有数据表。
> 这不是"配好了没触发"，是**根本没接**。

**Error Workflow 的 Web UI 绑定**（§4.10 的"手工步骤"）：
n8n 的 Error Workflow **只能在 Web UI 里指定，没有 API、也没有工作流 JSON 字段**。
所以这件事**在任何情况下都无法靠提交文件完成**——它必须写进部署手册（见 `docs/observability.md` §八
与 P10 的 `ops/runbook.md`），并要求附截图。**本轮没有部署，因此这一项是未验证。**

## 五 一条纪律

**"没有真实流量时只报告采集方法，不编造命中率、延迟或成本数字"**（引导词 P09 步骤 7）。

本文的写法就是这条纪律的落实：
- 能写的写**规则**与**依赖**；
- 不能写的（阈值、基线、触发记录）**一律留空并注明为什么**；
- **任何一处都不出现具体数字**，除非那个数字是实测出来的。

**判断依据**：如果一个人拿着本文去部署，他应该能一条条接上；
如果他想在本文里找一个"系统健康度"的数字——**本文故意没有**，因为那个数字必须是量出来的。
